# Plan: Elevator Sim — Open-Loop Feedforward → State-Space Control

## Background

### Current architecture

`SimulateElevator()` in `elevator_sim.h` runs a `TrapezoidProfile` and uses
`ElevatorFeedforward` (kV, kA, kG) to compute open-loop voltage at each
timestep. This is purely feedforward — there is no correction for model error,
gravity sag, or disturbances.

### Target architecture

Replace the feedforward-only loop with a full WPILib state-space loop:

- `LinearSystem<2,1,1>` — elevator plant (states: `[position, velocity]`, input:
  `[voltage]`, output: `[position]`)
- `KalmanFilter<2,1,1>` — observer estimating both position and velocity from
  position measurements only (velocity is a hidden state)
- `LinearQuadraticRegulator<2,1>` — LQR computing optimal voltage from state error
- `LinearSystemLoop<2,1,1>` — ties plant + LQR + Kalman filter together
- `TrapezoidProfile` — retained for setpoint generation; constraints are
  **user-provided, not auto-computed**
- `kG` feedforward — still computed internally from motor physics and added on
  top of the loop output for gravity compensation

---

## Key Design Decisions

### Plant model

kV and kA are derived internally in C++ from motor physics. They are NOT
user-facing parameters.

```
kV = gearing / (efficiency × Kv_motor × spoolRadius)     [V·s/m]
kA = (loadKg × spoolRadius × R) / (efficiency × Kt × gearing)  [V·s²/m]
kG = kA × 9.80665 × sin(angle)                           [V]
```

Continuous-time plant matrices (position-only output):

```
A = [[0,    1       ],   B = [[0      ],   C = [[1, 0]],   D = [[0]]
     [0, -kV/kA    ]]        [1/kA   ]]
```

### LQR tuning (new user-facing inputs)

- `qPositionMeters` — max tolerable position error (Bryson's rule Q diagonal)
- `qVelocityMPS` — max tolerable velocity error
- `rVolts` — max tolerable control effort
  Defaults: 0.05 m, 0.5 m/s, 12.0 V

### Kalman noise (fixed defaults, not user-exposed)

- State noise: `[0.05 m, 1.0 m/s]` (model uncertainty)
- Measurement noise: `[0.001 m]` (encoder noise)

### Motion profile constraints

`maxVelocityMPS` and `maxAccelerationMPS2` are **required** user inputs.
The "0 = use theoretical max" fallback is removed entirely.
Defaults: 2.0 m/s, 10.0 m/s²

### Gravity compensation

kG is still added as a static bias on top of `loop.U(0)` each timestep.
This is conceptually feedforward — the LQR corrects residual error.

### Current limiting

Unchanged. Applies after computing `vApplied = loop.U(0) + kG`.

  **Remove includes:**

  **Add includes:**

  **Inside the function, after cascade scaling and AngledElevatorSim construction:**

  ```cpp
  // Compute feedforward gains from motor physics
  const double kvMotor = motor->getKvRadPerSecPerVolt();
  const double ktMotor = motor->getKtNMPerAmp();
  const double rOhms   = motor->getROhms();

  if (kvMotor == 0.0 || ktMotor == 0.0 || spoolRadiusMeters == 0.0
      || efficiency == 0.0 || gearing == 0.0) {
    return emscripten::val::array();
  }
  const double kVVsPerMPS  = gearing / (efficiency * kvMotor * spoolRadiusMeters);
  const double kAVsPerMPS2 = (loadKg * spoolRadiusMeters * rOhms)
                             / (efficiency * ktMotor * gearing);
  if (kAVsPerMPS2 == 0.0) return emscripten::val::array();
  const double kGVolts = kAVsPerMPS2 * 9.80665 * std::sin(angleRadians);

  // Build LinearSystem<2,1,1> from motor physics
  wpi::math::Matrixd<2,2> A;
  A << 0, 1, 0, -kVVsPerMPS / kAVsPerMPS2;
  wpi::math::Matrixd<2,1> B;
  B << 0, 1.0 / kAVsPerMPS2;
  wpi::math::Matrixd<1,2> C;
  C << 1, 0;
  wpi::math::Matrixd<1,1> D;
  D << 0;
  wpi::math::LinearSystem<2,1,1> plant{A, B, C, D};

  // Kalman filter (fixed noise, not user-exposed)
  wpi::math::KalmanFilter<2,1,1> observer{
      plant, {0.05, 1.0}, {0.001},
      wpi::units::second_t(simTimestep)};

  // LQR (user-tunable q/r)
  wpi::math::LinearQuadraticRegulator<2,1> controller{
      plant, {qPositionMeters, qVelocityMPS}, {rVolts},
      wpi::units::second_t(simTimestep)};

  // LinearSystemLoop
  wpi::math::LinearSystemLoop<2,1,1> loop{
      plant, controller, observer,
      wpi::units::volt_t(12.0),
      wpi::units::second_t(simTimestep)};
  loop.Reset(wpi::math::Vectord<2>{0.0, 0.0});
  ```

  **Per-timestep control (replace feedforward.Calculate call):**

  ```cpp
  loop.SetNextR(wpi::math::Vectord<2>{
      nextProfileState.position.value(),
      nextProfileState.velocity.value()});

  loop.Correct(wpi::math::Vectord<1>{elevator.GetPosition().value()});
  loop.Predict(wpi::units::second_t(simTimestep));

  double vApplied = loop.U(0) + kGVolts;
  ```

  Then pass `vApplied` through `ClampVoltageForCurrentLimits` (unchanged).

  `kvRadPerSecPerVolt` is still needed for the back-EMF clamp calculation — keep it.

  **Loop termination:** Unchanged — runs until `totalProfileTime` or `maxSimSeconds`.

## Risk Notes

- **Divide-by-zero:** kA = 0 (massless carriage or zero efficiency) crashes
  `LinearSystem` construction. Guard returns empty array early.
- **Profile total time:** `profile.TotalTime()` must be called after
  `profile.Calculate(0, ...)`. This is unchanged from the current code.
- **Loop termination after profile:** The `AngledElevatorSim` continues to be
  driven by the last profile state once the profile finishes. The success check
  (position within 3 cm of goal) remains correct.
- **KalmanFilter stability:** With `C = [[1,0]]` (position-only), the system is
  observable and the Kalman filter is always detectable. No stability issues.
- **The optimizer's per-ratio profile constraints:** With user-provided fixed
  maxVelocity/maxAcceleration, some extreme gear ratios may fail the profile
  (e.g., too slow to reach the target in maxSimSeconds). This is correct
  behavior — those configs are simply marked as failures.
- **Back-EMF clamp:** `kvRadPerSecPerVolt` is still needed for the current
  limiter's back-EMF calculation. It is derived from `motor->getKvRadPerSecPerVolt()`
  and must be kept in scope.
